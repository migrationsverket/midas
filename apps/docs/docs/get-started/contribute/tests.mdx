# 🧪 Tester

Ett bidrag till kodbasen ska komma med minst ett test. Vi har flera sorters tester:

- **Komponenttester** körs i en riktig webbläsare och är de vi skriver flest av.
- **Tillgänglighetstester** kontrollerar alla stories i Storybook med axe.
- **Visuella tester** jämför skärmbilder av alla stories med godkända versioner.
- **E2E-tester** kontrollerar att paketen fungerar i en Next.js-app.
- **Enhetstester** testar kod som inte behöver en webbläsare.

## 🧩 Komponenttester

Komponenttesterna utgår från stories i Storybook. Med [portable stories](https://storybook.js.org/docs/api/portable-stories/portable-stories-vitest#composestories) renderar testet en story och kontrollerar sedan beteendet i en riktig webbläsare med [Vitest Browser Mode](https://vitest.dev/guide/browser/component-testing).

```bash
npx nx test components                            # Alla tester i ett paket
npx nx test components -- toast/Toast.spec        # En enskild fil
npx nx test components --browser.headless=false   # Med synlig webbläsare, användbart vid felsökning
```

Synlig webbläsare kräver WSLg eller en X-server om du kör WSL2.

Testerna i `@midas-ds/layout` körs i två storlekar, `desktop` (1024 × 768) och `mobile` (320 × 568). Ett test som bara gäller den ena storleken kan hoppa över den andra med `skip` i en `beforeEach`.

### Andra webbläsare

Som standard körs testerna i Chromium. Med `MIDAS_BROWSERS` väljer du andra webbläsare:

```bash
npx playwright install firefox webkit                     # En gång
MIDAS_BROWSERS=firefox npx nx test components
MIDAS_BROWSERS=webkit,mobile-safari npx nx test layout
MIDAS_BROWSERS=all npx nx test components                 # Alla
```

CI kör testerna i flera webbläsare på varje PR, och varje natt även i de två senaste versionerna av riktiga skrivbordswebbläsare. Profilerna beskrivs i [`tools/test-browsers`](https://github.com/migrationsverket/midas/tree/main/tools/test-browsers).

## ♿ Tillgänglighetstester

Med [@storybook/addon-a11y](https://storybook.js.org/docs/writing-tests/accessibility-testing) kontrolleras varje story med [axe](https://www.deque.com/axe/):

```bash
npx nx a11y storybook                     # Ljust läge
npx nx run storybook:a11y-dark-mode       # Mörkt läge
npx nx run storybook:a11y-forced-colors   # Högkontrastläge
npx nx run storybook:a11y-mobile          # Liten skärm
```

Automatiska tester hittar en stor del av bristerna mot [WCAG](https://www.w3.org/WAI/standards-guidelines/wcag/), men inte allt. Testa även med tangentbord och skärmläsare.

## 👀 Visuella tester

De visuella testerna tar en skärmbild av varje story och jämför den med en godkänd version som ligger i repot under `src/__screenshots__`. CI kör dem på varje PR och lägger en kommentar med skillnaderna om något har ändrats. De stoppar inte en merge.

Är ändringen avsiktlig lägger du till etiketten `visual:update` på PR:en. Då tas nya skärmbilder som committas till din branch. Granska dem under **Files changed**.

Du kan köra testerna lokalt, men skärmbilder från din egen dator kan skilja sig lite från dem i CI:

```bash
npx nx run components:visual
```

### Hoppa över stories

Ta bara en skärmbild per tillstånd i en komponent. Lägg till taggen `!snapshot` på stories som inte behöver någon:

```tsx
export const PrimaryWithAnotherLabel: Story = {
  args: {
    label: 'Just another label',
  },
  tags: ['!snapshot'],
}
```

## 🌐 E2E-tester

E2E-testerna kör [Playwright](https://playwright.dev/) mot en Next.js-app i `apps/next`, och kontrollerar att paketen går att bygga och köra där.

```bash
npx nx e2e next
```

## 🔧 Enhetstester

Kod som inte behöver en webbläsare testas med [Vitest](https://vitest.dev/guide/) i Node. Alla paket har inte enhetstester. [@nx/vitest](https://nx.dev/docs/technologies/test-tools/vitest/introduction) skapar kommandot `nx test <paket>` automatiskt när paketet har en konfigurationsfil för Vitest:

```ts title="vitest.config.mts"
import { defineProject } from 'vitest/config'

export default defineProject({
  test: {
    name: 'unit',
  },
})
```
